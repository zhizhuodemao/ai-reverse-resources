# 首轮调查与用户决策

本文是普通解混淆任务在 `SKILL.md` 之外唯一必读的首轮 reference。它只负责：

```text
确认机械准备结果
  → 直接阅读完整格式化源码
  → 建立当前可见画像
  → 通过字符串门
  → 形成候选问题和初步证据路线
  → 向用户提交第一次决策
```

它不规定具体 transform，不执行动态代码，不承担单步验收，也不继续路由其他 reference。

## 1. 准备验收

开始语义判断前确认准备报告至少包含：

```text
原始绝对路径
原始大小与 SHA-256
工作区和 run id
原始副本路径与 SHA-256
格式化视图路径与 SHA-256
Node 与 Prettier 版本
parser、命令和退出状态
格式化结果的 parse / syntax 状态
准备结束后的原始 SHA-256
```

必须满足：

- 源文件、原始副本和格式化视图是不同路径。
- 准备前后的源文件 SHA-256 相同。
- 格式化只写入派生文件。
- Prettier 来自已记录的本地可执行文件。
- 既有 run 目录和证据没有被覆盖。

任何条件不成立时停止在 `FORMAT_BLOCKED`，保留报告和 stderr。不要通过修改原始源码或静默更换工具绕过失败。

## 2. 完整直读

以格式化视图为唯一首轮阅读视图，按连续区间覆盖到 EOF。

建立阅读账本：

```text
file: steps/00_formatted.js
total_lines:
read_ranges:
  - start:
    end:
    notable_anchors:
remaining_ranges:
```

阅读顺序可以跨多轮，但必须连续推进。未读完整文件时只记录阅读进度，不提交完整画像，不让用户选择语义步骤。

先从源码片段观察，再用搜索、AST 和统计复核。重点查看：

- 入口、导出、公开 API 和初始化顺序。
- 长字符串、数组、字符码、异常字面量和 decoder。
- 高频 helper、wrapper、alias、间接调用和动态属性。
- 模块表、加载器、数字模块 ID、polyfill 和第三方边界。
- `eval`、`Function`、脚本注入、压缩载荷和运行时生成代码。
- Cookie、Storage、DOM、网络、时间、随机数、环境检测和反调试。
- VM 数据、加载器、解释器外围、宿主 binding、slot、入口和公开初始化。

不要根据文件名、课程主题、已知厂商或旧案例先给结构贴标签。

## 3. 画像分类

先判断结构属于哪一类：

| 分类 | 判断重点 |
|---|---|
| 真正混淆 | 有意隐藏值、调用、数据流、控制流或语义 |
| 压缩/转译 | 语义仍直接可追踪，只是短名、合并或编译产物 |
| 打包器 | 模块注册、缓存、加载、导出和 chunk 运行时 |
| polyfill/第三方 | 可识别的通用兼容层或外部库 |
| 环境检测/反调试 | 读取宿主差异、检测自动化或改变调试行为 |
| 动态载荷 | 运行时解码、生成、加载或执行的新代码 |
| VM 外围 | 先列解释器候选、数据区、宿主桥和公开初始化；数组、数字 ID 或 dispatcher 单独出现不足以确认 JSVMP |

再按模式家族记录，例如：

```text
字符串池、轮转、偏移、编码、decoder wrapper
常量表达式与字符码拼接
代理函数、间接调用、alias 和动态属性名
作用域隐藏、shadow 与 binding 混淆
不透明谓词、死分支和控制流平坦化
自修改、动态代码和压缩载荷
反调试、环境探测和遥测
打包器、数字模块、polyfill 和第三方内部
VM 加载器、数据区、宿主 binding 和 public init
```

模式家族数量、出现次数和影响范围是三个不同指标，不要混为“有多少种混淆”。

## 4. 统计和证据

每个候选写入 `ANALYSIS.md`：

```text
pattern_id:
name:
representative_snippets:
source_anchors:
family:
occurrences:
count_basis: exact | lower-bound | estimate
affected_ranges:
main_consumers:
dependencies:
classification:
evidence: Observed | Inferred | Unknown
confidence:
counter_evidence:
current_question:
known_static_facts:
evidence_gap:
route:
expected_gain:
risk:
initial_action:
```

要求：

- `Observed` 必须能回到源码锚点或工具原始输出。
- `Inferred` 必须说明推理链和可反证条件。
- `Unknown` 必须说明缺少哪个事实，不能用猜测补齐。
- 计数工具必须说明口径；不确定时使用下界或估计。
- 短变量、数字 key、模块 ID 和大数组本身都不是混淆证据。

## 5. 字符串门

必须检查：

- 转义字面量和字符码拼接。
- 字符串池、轮转、偏移和索引变换。
- Base64、RC4、自定义编码和压缩文本。
- decoder wrapper、别名、缓存和动态属性名。
- 运行时 key、动态载荷和消费者。

结果分三类：

1. 确认是真实字符串隐藏，并阻碍入口、属性、调用或主要数据流：作为第一个语义推荐。
2. 只是普通字面量、第三方数据、压缩资源或 VM 字节数据：记录理由，跳过字符串 transform。
3. 静态无法确认：标记 `Unknown`，把最小证据缺口写成候选问题。

字符串优先只决定推荐顺序，不代表已经获得执行 transform 或运行 decoder 的授权。

## 6. 依赖与候选问题

把模式画成依赖关系，而不是平铺清理清单：

```text
隐藏字符串
  → 动态属性名
  → helper / alias 消费者
  → 模块入口或宿主 binding
  → 后续算法与 VM 边界
```

每个高价值候选改写为可证伪问题：

```text
当前要回答什么？
已经观察到什么？
静态还缺少什么？
取得哪个事实后才能继续？
结果怎样改善阅读、观测或交接？
结果怎样映射回当前视图？
```

“解字符串”“清理控制流”只是模式名称，不是合格问题。

## 7. 证据路线与排序

首轮只做初步分流：

| 路线 | 使用条件 |
|---|---|
| `static` | AST、作用域、引用、常量和数据流已经足够 |
| `local-exec` | 闭合 decoder、冻结输入、无宿主依赖 |
| `dynamic` | 缺少的事实只有运行时才能取得 |
| `hybrid` | 静态定位、动态取证、AST 写回 |
| `blocked` | 缺少可信执行条件、输入或授权 |
| `handoff` | 需要系统补环境、真浏览器、算法或 VM 内部能力 |

依次比较：

1. 与当前入口、输入、输出和用户方向的相关性。
2. 对关键调用关系、属性名和数据流的解锁能力。
3. 对后续动态观测、算法分析或交接的改善。
4. 影响范围和消费者数量。
5. 证据强度。
6. 语义风险、运行风险和成本。
7. 是否仍属于 AST 边界。

给出 `recommend`、`ask`、`skip`、`blocked` 或 `handoff`，但不要在首轮直接执行语义步骤。

## 8. 第一次用户决策

先用普通语言汇报：

```markdown
## 当前画像

- 已完整阅读：
- 当前可见模式：
- 真正混淆：
- 打包器、第三方或编译产物：
- 字符串门：
- 关键依赖：
- 仍然 Unknown：

## 下一步

1. 推荐：要解决的问题、预计得到的结果、证据路线和风险。
2. 替代：真正不同的分析方向及其代价。
3. 暂停或交接：当前已具备的成果和剩余问题。
```

不要问用户“选 static 还是 hybrid”“要不要做 binding analysis”。把技术选择翻译成结果。

## 9. 首轮完成条件

只有同时满足以下条件，才进入 `READY_FOR_USER_DECISION`：

- 机械准备报告通过。
- 格式化视图已连续读到 EOF，阅读账本无缺口。
- 当前可见模式都有源码锚点、分类和证据等级。
- 家族数量、出现次数和影响范围已经区分。
- 字符串门已经得出确认、跳过或 Unknown。
- 高价值候选已经改写为问题并建立依赖。
- 每个提交给用户的候选都有初步路线、收益、风险和边界。
- 已准备 2～3 个互斥、使用结果语言表达的选项。

首轮只是当前视图，不是永久全集。用户选择一个步骤后，结果必须回到最新源码重新审视。
