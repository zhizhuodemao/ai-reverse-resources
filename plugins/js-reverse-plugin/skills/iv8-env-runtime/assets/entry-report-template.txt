========================================================================
P1 入口定位结论报告（模板）
用法：逐字段填满。三条边界证据（上一层没有 / 下一层已有 / 中间结果==最终结果）
必须同时齐备，末行才允许写「已定位」；任一字段只有猜测或调用栈痕迹 → 写「未定位」。
说明见 references/part1-entry-location.md §7-8。
========================================================================

目标字段：            （字段名 + 位置：URL query / header / body / cookie / storage + 真实样例值）
真实出口：            （URL / XHR.open / fetch / sendBeacon / cookie setter / storage setter / return / callback）
直接相关 JS：         （脚本 URL + 生成帧函数名；scriptId 会过期，记 URL）
入口类型：            （函数式 / 拦截式 / 事件式 / 状态机式 / 采集式 / 下发式）
来源类型：            （本地生成 / 已有状态搬运 / 服务端下发 / 未确认）
前置状态：            （触发前 JS 是否加载、init 是否完成、cookie/storage/config 是否存在）
主动触发方式：        （调函数 / 触发 XHR/fetch / 事件 / timer / 队列 / getter）
输入参数：            （this、arguments、URL、method、headers、body、config、事件对象）
上一层没有的证据：    （上一层输入里目标字段不存在的动态观察）
下一层已有的证据：    （下一层输出里目标字段已出现的动态观察）
中间结果==最终结果证据：（哪个变量/返回值逐字符等于最终出口值）
输出读取方式：        （从 URL/header/body/cookie/storage/netLog/return/callback 的哪里读）
对照实验：            （不触发/触发/改输入/清状态/重放后的对照结果）

结论：                （已定位 / 未定位）
