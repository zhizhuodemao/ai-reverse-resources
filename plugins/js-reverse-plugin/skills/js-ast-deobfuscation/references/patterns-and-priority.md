## 1. 使用时机与边界

只在以下准备完成后读取本 reference：

1. 原始输入已经冻结并记录 hash。
2. Node Prettier 已对派生副本完成格式化。
3. 模型已经按连续区间直接阅读完整的格式化 JavaScript。

先记录真实代码事实，再借助本 reference 命名和归类。不得从文件名、课程主题、历史案例或本清单反推当前样本必然具有某种结构。

这里列出的是常见家族，不是固定 detector 列表，也不是执行顺序。一个文件可能没有其中任何一种，也可能出现新的组合。

首轮结果必须称为“当前视图中可见的模式”。字符串恢复、载荷解包或其他步骤可能暴露新的结构。

## 2. 从完整源码建立画像

### 2.1 先区分代码角色

同一种表面形态在不同角色中含义不同。先把相关区域分为：

- 业务逻辑。
- 入口、导出和公开 API。
- 打包器与模块运行时。
- polyfill 和第三方依赖。
- 编译、转译与压缩产物。
- 动态载荷和加载器。
- 环境检测、反调试、监控与遥测。
- VM 数据、解释器、宿主桥和外围适配层。
- 当前无法分类的区域。

分类必须有源码锚点。不能因为代码难读，就自动标为混淆。

### 2.2 每个候选都保存证据层级

- `Observed`：源码或已限定范围的运行日志直接证明。
- `Inferred`：由多项事实支持，但仍包含解释。
- `Unknown`：缺少关键证据，不能继续断言。

例如：

- 对象中存在 getter/setter 是 `Observed`。
- 它为宿主变量提供 VM 读写能力，可以是有静态连接支持的 `Inferred`。
- 某次真实运行一定访问该 slot，则在没有运行证据时仍是 `Unknown`。

### 2.3 给每个候选建立源码锚点

至少记录：

- 声明或入口位置。
- 代表性源码片段。
- 主要消费者位置。
- 与入口、导出、网络、Cookie、Storage、加密、动态代码或 VM 的关系。
- 仍需复读的相邻区域。

自动统计只能补全数量和定位遗漏，不能替代源码锚点。

## 3. 统计口径

### 3.1 分开三个数字

- **模式家族数量**：当前视图中可区分的结构类型数。
- **出现次数**：某一家族匹配到的节点、调用点、声明或区域数。
- **影响范围**：该家族实际阻碍的入口、模块、函数、数据流或源码区间。

不能把“发现 8 个家族”和“匹配 800 次”写成同一个数字。

### 3.2 先定义计数单位

不同家族使用不同单位，必须写明：

- 字符串隐藏：池条目、decoder、调用点、动态消费者分别计数。
- helper/proxy：声明、属性和调用点分别计数。
- 控制流隐藏：dispatcher、case、受控函数分别计数。
- 动态代码：生成点、执行点和载荷分别计数。
- 数字模块：模块工厂、加载调用、唯一依赖边分别计数。
- VM 宿主：入口、slot、descriptor、binding 和公开导出分别计数。

### 3.3 标记精度

每个数字标为：

- `exact`：边界明确并完整统计。
- `lower-bound`：至少有这么多，但仍有动态或不可解析部分。
- `estimate`：抽样或启发式估计，并写明原因。

同一语法节点同时命中多个表面特征时，应按真实结构去重，不能为了显得复杂而重复累计。

### 3.4 不把静态存在写成运行事实

模块、字符串、分支、slot 或 API 在源码中存在，只证明它们可达或可被使用，不证明：

- 当前入口会执行它。
- 当前输入会走到它。
- 它影响最终输出。
- 它属于业务算法。

画像中分别记录“静态存在”“静态可达”和“已观察执行”。

## 4. 依赖与优先级

### 4.1 建立模式依赖

常见依赖关系包括：

- 字符串隐藏遮住属性名、模块名、API 和 dispatcher token。
- 表达式隐藏遮住分支常量和索引。
- helper/proxy 遮住真实调用和操作符。
- 动态载荷遮住新的源码层。
- 打包器边界遮住业务入口和第三方依赖边界。
- VM 宿主短名遮住公开入口、slot 和宿主能力。

依赖边只表达“阻挡、揭示、消费或约束”，不能冒充运行数据流。

### 4.2 字符串是唯一固定检查门

每个样本都必须检查真实字符串隐藏。

- 确认存在时，把字符串恢复作为第一个语义推荐。
- 不存在时记录证据，继续按收益选择。
- 静态无法确认时标为 `Unknown`，不要制造空 transform。

字符串步骤之后没有固定顺序。必须重新阅读最新视图并重新排序。

### 4.3 收益排序

比较候选时考虑：

1. 是否直接服务当前分析方向；用户尚未给出下游问题时，是否明显改善整体理解。
2. 是否揭示入口、调用关系、关键数据流或多个后续结构。
3. 影响范围是否足够大。
4. 证据是否足以限定边界。
5. 是否可能改变 binding、副作用、异常路径或业务语义。
6. 所需成本是否合理。
7. 是否仍属于 AST 解混淆边界。

出现次数不是唯一收益指标。一个只出现一次的载荷入口可能比数千个无关短名更重要。

### 4.4 分流含义

- `推荐处理`：明显阻碍理解或后续分析，证据和边界足够。
- `必须询问`：涉及删除、高风险重写、语义命名、动态执行或范围扩张。
- `默认跳过`：主要是美观、无关依赖或不影响当前目标。
- `当前阻塞`：候选相关，但缺少证据、输入、环境或稳定匹配。
- `阶段交接`：继续处理需要系统补环境、真实浏览器或 VM 内部能力。

## 5. 字符串隐藏

### 可观察形态

- 十六进制或 Unicode 转义字面量。
- 大型字符串数组、旋转数组和索引偏移 decoder。
- Base64、字符码拼接、自定义字母表或流式解码。
- decoder wrapper、别名、缓存和多层索引。
- 通过字符串隐藏的属性名、模块名和 API。
- 一段内嵌载荷同时初始化字符串、配置和二进制记录。

### 常见误判

- Base64 可能只是图片、证书、压缩资源或普通业务数据。
- 大数组可能是字典、模型、协议表或 VM 数据。
- 转义字面量可能只是压缩器输出。
- 池中存在某个字符串，不证明对应路径执行。

### 还需要直接读取什么

- 载荷的完整生产链和消费链。
- 初始化发生在加载期还是按需调用。
- decoder 是否依赖环境、随机数、时间、闭包或外部状态。
- 消费者使用常量索引还是动态索引。
- 解码结果是否同时包含非字符串数据。

### 依赖、统计与证明边界

分别统计载荷、池、decoder、调用点和消费者。动态索引时，即使不能替换单个调用点，完整池和稳定索引仍可能是高收益分析产物。

静态只能证明池内容和连接关系时，不得声称某个字符串参与最终算法。

### 分流

- 确认真正隐藏属性、API、模块或控制信息时：推荐首先处理。
- 需要执行 decoder、读取运行时 key 或解压载荷时：先标出证据缺口，按方法 reference 决定 static、hybrid 或 blocked。
- 删除初始化器、缓存或原始载荷时：必须询问，并检查消费者和副作用。
- 只是资源、第三方数据或 VM 字节记录时：默认跳过或原样保留。
- 后续必须解释 VM 记录或字节码时：交接 VM 分析。

## 6. 表达式隐藏

### 可观察形态

- 括号属性访问代替点访问。
- 字符串拼接隐藏关键名称。
- 十六进制数、布尔技巧、`void 0` 和冗余括号。
- 逗号表达式、序列表达式和间接调用。
- 常量算术、位运算和可折叠条件。

### 常见误判

- 括号访问可能来自动态属性、关键字兼容或生成器。
- 间接调用可能故意改变 `this`。
- 逗号表达式可能保留前项副作用。
- 十六进制数字可能是协议位掩码、哈希常量或地址。

### 依赖、统计与证明边界

按表达式节点和受影响消费者统计，不把同一表达式中的每个字面量都算作独立模式。

只有求值顺序、`this`、异常和副作用边界明确时，才能把它列为低风险候选。

### 分流

- 能显著揭示条件、索引或关键调用且边界确定时：推荐处理。
- 涉及 getter、隐式转换、`this`、异常或副作用时：必须询问或当前阻塞。
- 只改善外观而不影响分析时：默认跳过。

## 7. helper、proxy 与 alias

### 可观察形态

- 对象属性包装二元或一元操作。
- wrapper 只转发函数调用或构造调用。
- 多层函数别名、属性别名和立即赋值。
- 模块加载器、导出包装和兼容层代理。

### 常见误判

- wrapper 可能绑定 `this`、使用 `arguments`、捕获闭包或改变异常。
- alias 可能只是赋值时刻的快照，不是永久等价关系。
- helper 可能承担缓存、计数、遥测或环境适配。
- 加载器和兼容包装可能是基础设施，不是混淆。

### 还需要直接读取什么

- 完整函数体和所有引用。
- 写入、重新赋值和动态属性访问。
- 调用点的 `this`、参数展开和返回值使用。
- wrapper 是否跨越业务、第三方或 VM 边界。

### 依赖、统计与证明边界

分别统计声明、属性、调用点和影响范围。同一个 helper 被大量消费时，出现一次也可能有高解锁收益。

静态连接只证明可能的转发关系；发生过重新赋值时，不能把所有时刻视为同一值。

### 分流

- 单语句、无副作用、无动态状态且阻碍关键调用时：推荐处理。
- 使用 `this`、`arguments`、闭包状态、mutation 或动态属性时：必须询问或阻塞。
- 属于无关 polyfill、模块兼容层且不阻碍分析时：默认跳过。

## 8. binding 与语义命名

### 可观察形态

- 大量单字母、随机或重复短名。
- 相同文本名称出现在多层作用域。
- 公开导出、入口和宿主角色被压缩名称遮住。
- 属性名和局部 binding 混用相同文本。

### 常见误判

- 短名可能只是压缩，不是独立混淆。
- 相同文本不代表同一个 binding。
- 静态角色名称不证明真实运行路径或业务语义。
- 无法恢复作者原名，不等于无法建立可用坐标。

### 依赖、统计与证明边界

按词法 binding、声明和引用分别统计，不能按文本出现次数统计“变量”。

优先使用中性角色名，例如 loader、cache、entry、slot 或 record。业务语义名称需要更强证据。

### 分流

- 名称明显阻碍入口、调用关系或阶段交接，且角色可静态证明时：推荐中性命名。
- 多个语义解释成立或准备使用业务名称时：必须询问。
- 只是无关第三方内部短名时：默认跳过。
- 涉及 VM Opcode、栈效应或算法含义时：交接 VM 分析。

## 9. 控制流隐藏

### 可观察形态

- 不透明谓词和恒真、恒假分支。
- `while`、`switch` 和 dispatcher 驱动的基本块重排。
- 静态顺序串、case 索引和手工状态机。
- 异常、递归或回调驱动的非线性流程。

### 常见误判

- 普通状态机、协议解析器、解释器和编译器也大量使用 `switch`。
- `while (true)` 可能是正常消费循环。
- 看似死分支可能由 getter、Proxy、时间、随机数或环境决定。
- VM dispatcher 属于下一阶段，不是普通控制流平坦化。

### 还需要直接读取什么

- dispatcher 的来源、更新和全部消费者。
- case 完整性、fallthrough、break、continue、return 和 throw。
- 状态是否被闭包、异常或外部事件修改。
- 该结构是业务控制流、基础设施还是 VM 解释器。

### 依赖、统计与证明边界

按 dispatcher、受控函数、case 和基本块统计。不能看到一个 `switch` 就计作控制流平坦化。

### 分流

- 顺序和终止边界可证明，且直接阻碍目标路径时：可推荐处理。
- 涉及异常路径、外部状态或大范围重写时：必须询问。
- 正常状态机或无关基础设施：默认跳过。
- VM dispatcher、虚拟控制流或 Opcode 语义：交接 VM 分析。

## 10. 动态代码与载荷

### 可观察形态

- 直接或间接 `eval`。
- `Function`、构造器链和字符串生成函数。
- 字符码、Base64、压缩数据或模板拼出的源码。
- 运行时下载、解密或注入的新脚本。

### 常见误判

- `Function` 可能是能力探测或 polyfill。
- 字符串可能是模板、查询或数据，而不是 JavaScript。
- 动态代码存在不证明它被当前入口执行。

### 还需要直接读取什么

- payload 的生产、执行和结果消费位置。
- 是否依赖真实网络、页面生命周期、环境或用户输入。
- 执行前后可能发生的全局写入、注册和副作用。
- 解包后是否暴露新的混淆层。

### 依赖、统计与证明边界

分别统计生成点、执行点、唯一载荷和消费者。相同 payload 被多次执行时不能重复算作多个家族。

### 分流

- payload 阻碍关键逻辑理解时：推荐先揭示 payload。
- 需要执行完整未知代码、真实网络或宿主权限时：必须询问。
- 只需保留动态边界而与当前方向无关时：默认跳过。
- 缺少 payload、trigger 或环境时：当前阻塞。
- 载荷进入 VM 字节码或需要真实浏览器行为时：交接相应阶段。

## 11. 反调试、环境检测与遥测

### 可观察形态

- `debugger`、定时守卫、函数源码完整性检查。
- console 覆盖、无限循环或调试器时间差。
- `navigator`、`window`、`document`、Cookie、Storage 和 location 探测。
- API 存在性、属性描述符、反射和 native-code 检查。
- 监控、性能、错误上报和遥测调用。

### 常见误判

- 环境探测可能决定正常兼容分支。
- 遥测可能参与初始化、配置或业务开关。
- `Function("return this")` 也可能是通用全局对象获取。
- 发现反调试信号不等于可以删除。

### 依赖、统计与证明边界

按守卫、探测点、被探测 API 和受控分支统计。环境读取只证明发生访问，不证明它进入最终算法。

### 分流

- 直接阻碍阅读、触发或动态取证时：作为候选提交。
- 删除、绕过或修改环境分支时：必须询问。
- 不影响当前目标时：默认跳过并保留边界。
- 需要系统补环境或真实浏览器状态时：交接运行环境阶段。

## 12. 打包器、数字模块、polyfill 与第三方代码

### 可观察形态

- 数字或短字符串作为模块键。
- 模块工厂表、缓存和加载函数。
- 大量内部依赖边和入口包装模块。
- 多版本 polyfill、兼容层和第三方源码片段。

### 常见误判

- 数字模块 ID 是打包器常见表示，不自动等于恶意混淆。
- 短变量可能来自发布构建或压缩。
- 模块存在不代表运行时加载。
- 猜出的模块业务名称不能当作证据。
- 识别出第三方库不代表可以删除。

### 还需要直接读取什么

- 模块表、缓存、加载器和入口包装的真实结构。
- 直接依赖、反向依赖和公开导出。
- 内嵌版本、许可证、字面量和结构证据。
- 目标业务入口实际依赖哪些组件。

### 依赖、统计与证明边界

分别统计模块、加载调用、唯一依赖边、入口和分类后的第三方组件。文本搜索得到的数量只能作为下界，不能覆盖 AST 统计。

官方名称、版本或角色只有在源码、版本记录、依赖图或导出行为形成一致证据时才能接受。无法证明时保留 ID 或使用中性名称。

### 分流

- 模块边界阻碍业务入口、调用关系或第三方区分时：推荐恢复稳定角色或有证据的名称。
- 需要引入高语义名称、删除依赖或改变加载语义时：必须询问。
- 与目标无关的 polyfill 和第三方内部短名：默认跳过。
- 缺少足够匹配证据时：保留原 ID，标为当前阻塞而不是猜名。

## 13. JSVMP 宿主边界

### 可观察形态

- 外层加载器、VM 数据区、解释器和数字入口。
- getter/setter descriptor 将 slot 连接到外层 binding。
- 公开 API、初始化函数和宿主调用桥。
- VM 外围的加密、网络、时间、随机数或环境适配。

### 常见误判

- descriptor 证明能力连接，不证明真实运行读写。
- 同一 binding 的前后连接是潜在边界，不是执行轨迹。
- 赋值 alias 可能是当前位置快照。
- 解释器中的 `switch` 不应按普通控制流平坦化处理。
- 外层角色可命名，不代表 Opcode 或业务算法已恢复。

### 还需要直接读取什么

- VM 数据、入口、解释器和公开导出的连接位置。
- slot descriptor 的 getter、setter 和对应 binding。
- 外层 helper、宿主 API 和网络出口。
- 哪些结构位于 VM 外围，哪些已经进入虚拟语义。

### 依赖、统计与证明边界

分别统计入口、slot、descriptor、binding、公开导出和潜在能力边。静态连接图不得写成运行轨迹。

中性名称用于建立稳定坐标；实际 slot 使用、运行路径和 VM 内部算法仍是 `Unknown`，除非有相应运行或 VM 证据。

### 分流

- 清理外围字符串、载荷、公开入口和宿主角色能改善后续分析时：推荐处理。
- 高语义业务命名、删除解释器外围或改变宿主连接时：必须询问。
- VM 内部 Opcode、PC、值栈、帧栈和虚拟控制流：默认不处理并交接 VM 分析。
- 需要系统补环境才能观察公开出口时：交接运行环境阶段。

## 15. 每步后的重新画像

每个通过验收的步骤后：

1. 重新直接阅读最新分析视图的受影响区域和新暴露区域。
2. 重新统计家族数、出现次数和影响范围。
3. 新增新暴露模式。
4. 合并重复项。
5. 修正误判、证据层级和依赖。
